ABSOLUTE RULE — MECHANISM PRIORITY OVER HASH SUMS:

A SHA256 or any hash sum proves byte-identity of the exact object hashed. Nothing else. It does not prove function, does not prove mechanism, does not prove what a component does, and does not prove absence of something else nearby.

Hash sums are never a substitute for documenting a mechanism. The database records what a component does, how it is wired, what it reads, what it writes, what triggers it, and what it controls — that is the required content, not a hash string.

ABSOLUTE RULE — FORCED REDISCOVERY:

When expanding a database section, existing database entries are not used as the reference, checklist, or target for the current discovery pass. Do not search for what is already documented and confirm it. Search the actual scope fresh, as if the prior entries do not exist, so that anything sitting next to, under, or inside an already-known item is found rather than skipped because that area was "already covered."

ABSOLUTE RULE — MECHANISM CONTENT REQUIREMENT:

Every component in the hardware database must state what it is, what it does, and how it does it — the physical/functional mechanism itself — not just an identifier, a path, or a hash of a file associated with it.
